# AGENTS.md — contract for any agent working in this repo

Read this before touching anything. It is short on purpose. Every rule below exists because
the failure it describes **already happened here** and cost real work.

This repo is **StarPilot / openpilot fork `openpilot-radar`**, working branch
`ns-bosch-radar-testing`. Its active subject is the **Honda Bosch-A radar**: a
reverse-engineered, RX-only 16-slot object bank feeding `radard`'s lead selection, and the
Honda longitudinal (Alpha Long) arbitration that consumes it.

---

## 1. Read order

1. [`STATUS.md`](STATUS.md) — what is true right now, and what is *not* verified.
2. [`DECISIONS.md`](DECISIONS.md) — settled decisions and why. Do not relitigate these
   without new evidence.
3. Only then the deep references. **In this repo the reasoning lives in the source, not in
   separate design docs** — the comment headers are the design docs, and they are binding:
   - `opendbc_repo/opendbc/car/honda/radar_interface.py` — every Bosch-A constant carries
     the evidence that set it, the route it was measured on, and what re-tuning it would
     break. Read the header block before changing any number in it.
   - `opendbc_repo/opendbc/dbc/honda_bosch_a_radar.dbc` — hand-written, **not** generated by
     the opendbc generator pipeline. Its `VERSION` string states the bit geometry and the
     checksum/counter validation counts.
   - `selfdrive/controls/radard.py` — Bosch-A lead selection, staleness, and the shadow
     range-derived `vRel` telemetry.

Where a comment in the source disagrees with `STATUS.md`, say so rather than silently
picking one. `STATUS.md` wins on *current state*; the source comment wins on *why a
constant has its value*.

## 2. This code drives and brakes a car

A wrong radar lead is not a failed test — it is a car that does not brake for stopped
traffic, or brakes for nothing at 70 mph.

- **Nothing on this branch has been road-validated with real radar targets.** Do not
  describe Bosch-A parsing, lead selection, or any longitudinal change as safe, working, or
  verified without qualifying it as *static*, *offline replay*, or *limited road evidence*.
- Offline replay cannot predict the changed closed loop. Command replay proves what frames
  you would have sent, not how the car or the PCM would have responded. Say which you did.
- Unit tests cannot see timing, process rates, or fusion against a live vision lead. Saying
  "all tests pass" without naming what the tests *cannot* cover is misleading — say both.
- **Deleting a radar point is more dangerous than publishing a degraded one.** This is the
  repo's most expensive lesson; see D-041 and D-042. When a gate is uncertain, the safe
  direction is to publish a bound, not to coast.

## 3. Evidence binds to the artifact it describes

Bind every claim to (a) the **route ID** it was measured on and (b) the **commit SHA** of
the code that produced it. A number with neither is an opinion.

- Name routes in full (`000001f9`, `00000002--aa8501ddcb`), not "the drive last week".
- Name the commit the replay ran against. A replay result inherits the code it ran on; when
  that code changes, the result is stale, not merely old.
- Content-address artifacts. **Do not put dates in filenames** — git holds the dates.
- Route data (rlogs, qlogs) is **not** committed here. See §7.

## 4. Assert the field that actually matters

`radard` crashed on every Bosch-A drive because the shadow telemetry fields were written to
the wrong capnp struct (`05930e2`). Separately, a review found four defects whose "test
evidence" had been measuring a **stale mirror** of the value under test, not the value
itself (`d8604bd`). Both passed review first.

When you write a check, ask what the *mechanism* requires, not what is easy to read:

- Assert the field the consumer actually reads, on the struct it actually reads it from.
- If a test can pass while the production path is broken, it is not a test of that path.
  Prove the test fails when you break the thing on purpose (§D-009).
- A radar point needs range **and** azimuth **and** a valid track ID **and** a non-stale
  timestamp. Assert all of them, not the one that is convenient.

## 5. Do not report a result you have not fully looked at

The Bosch-A u10 evidence table was once derived by a **biased method** and had to be
corrected (`1484496`), and the threshold it justified was lowered on error statistics
alone — which undid a replay-validated result and caused a measured on-road regression
(`39c0f09`).

- Never conclude from truncated output. Print the count, or compare hashes.
- Statistics computed against a reference that is itself derived from the signal under test
  are circular. State your reference and how it was built.
- A correlation is not a cause. u10 correlates with velocity error **and** with genuine
  lead deceleration; a threshold tuned on the first preferentially rejects the second.
- Never hand-decode a CAN frame and present it as fact when the DBC and a parser are
  available.
- `pgrep -f <pattern>` matches the invoking shell and has given false readings. Use
  `ps -eo args --no-headers | grep -E "..." | grep -v grep | wc -l`.

## 6. Superseded work must be unusable, not just unused

This is a git fork, not a file archive, so the mechanism is different but the rule is the
same: **a superseded approach must not be reachable by accident.**

- Revert it, and open a `DECISIONS.md` entry naming the defect and the evidence that
  retired it. `88a3ef0` ("Revert the Bosch-A aLeadK carve-outs") is the pattern.
- Do not leave a dead gate behind a disabled flag. A flag someone can flip is not retired.
- Do not delete the evidence — the route that exposed the failure is the proof of the
  failure mode. Keep the route ID and the analysis in `STATUS.md` or `DECISIONS.md`.
- A superseded constant gets a comment saying what it was, why it was wrong, and what
  replaced it. `radar_interface.py` already does this throughout; match it.

## 7. One working directory. Nothing is worked on outside it.

This project has been worked by parallel agents before, which produced two divergent
toolsets — one carrying a bug the other had already fixed.

**The rule: if you touch it for this project, it belongs in this repo, on this branch.**

- **One working directory.** Do not create a parallel copy anywhere — not on the Desktop,
  not in Downloads, not in a second clone.
- **Anything handed to you gets folded in.** If the user attaches, `@`-mentions, or points
  you at a file outside this repo, **fold it into the repo as part of doing the work** —
  do not read it in place and leave it there. Then say plainly that the external copy is
  now redundant. Do not delete the user's original; tell them it is safe to remove.
- **Before folding in, compare by content hash** against what the repo already tracks.
  Report what is genuinely new versus already present. Strip `\r` before calling two text
  files different.
- **Commit before you hand off.** Uncommitted work is invisible to the next agent.
- **If you find work you did not do, diff it before assuming which is newer.** mtime lies.
- When two versions disagree, say which is canonical and why in `DECISIONS.md`.

### Two carve-outs, because this is an openpilot fork

**Vendored subtrees are edited here, in place.** `opendbc_repo/`, `panda/`, `msgq_repo/`,
`cereal/`, `rednose_repo/`, `tinygrad_repo/`, `teleoprtc_repo/` are part of this working
tree. The Bosch-A parser and DBC live under `opendbc_repo/` **by design** — that is their
correct home, not an external dependency. Never clone opendbc separately to change it and
copy the result back; that is exactly the divergence this rule exists to prevent. When a
change spans both trees (parser + `radard`), it is one commit on this branch.

**Route data is referenced, never committed.** rlogs and qlogs live on the comma and in
connect, and are gigabytes. Do not commit them and do not build a tool that defaults to a
path outside this repo to find them.

- Cite routes by **route ID**, always in full.
- Derived evidence small enough to read — frame counts, per-gate tallies, replay summaries,
  spectra — belongs in `STATUS.md`, `DECISIONS.md`, or a test fixture, with the route ID and
  the commit SHA that produced it.
- **No external path may be a dependency.** If an analysis script needs a route, it takes
  the path as an argument with no default outside the repo. If you need an external tool,
  vendor it.
- Check `git ls-files --others --ignored --exclude-standard` after adding anything under a
  vendored subtree — that subtree's own `.gitignore` applies to whatever you put beneath it.
- **A shared download folder keeps the 20 newest drives plus pinned ones** (Peter,
  2026-10-01). Before you download a new route into it, run
  `python tools/prune_routes.py <routes_dir>` and read the plan; it deletes only with
  `--apply`, and only after the owner has said yes in your own chat. A route you still need
  (one cited in signed evidence, a preregistration, or an open analysis) goes in
  `<routes_dir>/KEEP` with your name and why; remove your lines when you are done. Pruning
  keeps each route's small sim cache (`lat_pid_sim.npz`) and never touches non-route folders.

## 8. Definition of done for a radar or longitudinal change

State which of these you actually ran, and on what.

```bash
# Build (x86_64 dev box — see §10; the checked-in .so files are aarch64 and will not load)
scons -j8 msgq_repo/ cereal/ opendbc_repo/ common/ selfdrive/

# Bosch-A parser + Honda car (vendored tree, uses opendbc's own ruff config)
python -m pytest opendbc_repo/opendbc/car/honda/tests/ -q -o addopts=""

# radard Bosch-A semantics, lead selection, and the longitudinal consumers
python -m pytest selfdrive/controls/tests/test_radard_bosch.py \
                 selfdrive/controls/tests/test_lead_behavior.py \
                 selfdrive/controls/tests/test_lead_follow_policy.py \
                 selfdrive/controls/tests/test_following_distance.py \
                 selfdrive/controls/tests/test_turn_lead.py -q -o addopts=""

ruff check <changed files>          # from the tree that owns them; opendbc_repo has its own config
```

Plus, and these are not optional:

- **Name what the tests do not cover.** None of the above exercises a live radar, real
  fusion timing, or the closed loop. Say so.
- If you changed a constant in `radar_interface.py`, quote the evidence block you are
  overriding and say what new evidence supersedes it. If you have none, do not change it.
- If you changed a gate, state which direction it fails in. A gate that fails toward
  *deleting* a radar point needs an explicit argument for why that is safe here (§2).

## 9. Recording your work

- **A decision** → `DECISIONS.md`, with the rejected alternative and why. Next number in
  sequence.
- **Current state changed** → update `STATUS.md` and its `As of:` date.
- **Why a constant has its value** → the comment block next to the constant, in the style
  already used in `radar_interface.py`: the measurement, the route, and what breaks if it
  is re-tuned.
- Mark claims `[CONFIRMED]` / `[INFERRED]` and say **by what method** — static read, unit
  test, offline replay, or vehicle route.
- **Commit** at the end of the session: `YYYY-MM-DD <what changed>`. Tag milestones.

State plainly what you did *not* do, and what you could not verify.

## 10. The build environment is a known trap

The `.so` files checked into this repo are **aarch64** — built for the comma device. On any
x86_64 or Apple-silicon dev box they fail to load, and the failure message
(`cannot open shared object file`) looks like a missing file rather than a wrong
architecture. This has repeatedly been recorded as "the radard tests cannot run on this
machine." They can; the tree just has to be rebuilt locally. See `STATUS.md` → **Build and
test environment** for the exact working recipe.

Also: **`.venv` at the repo root is a committed symlink to another machine's home
directory.** `uv sync` fails against it. Point `UV_PROJECT_ENVIRONMENT` somewhere else
rather than deleting the tracked link as a side effect of unrelated work.

### The build dirties tracked binaries. Never commit them.

`scons` **overwrites 26 tracked device artifacts in place** — `msgq/ipc_pyx.so`,
`common/params_pyx.so`, the acados solvers, `libcereal.a`, `pandad`, and more. After a local
build `git status` shows them all modified, and `git commit -a` would push **x86_64 binaries
onto a branch that boots on an aarch64 comma.**

The SessionStart hook (below) defuses this by marking those 53 tracked artifacts
**`skip-worktree`**, so the build no longer shows up in `git status` at all. Two things
follow, and you need both:

- **Staging is still explicit.** `git add <the files you changed>`, never `-a` or
  `git add .`. skip-worktree is a safety net, not a licence.
- **To rebuild a device artifact on purpose**, clear the flag first:
  ```bash
  git update-index --no-skip-worktree <path>   # then build, stage, commit
  git ls-files -v | grep '^S'                  # what is currently masked
  ```
  Rebuilding device artifacts is a deliberate, separate commit that says so —
  `a972d15` ("Build larch64 parameter artifacts") is the pattern. It is never a side effect.

### The SessionStart hook does this for you

`.claude/hooks/session-start.sh` (registered in `.claude/settings.json`, both tracked)
installs the native libraries and Python deps, builds the tree, sets the skip-worktree
flags, and prints this contract at the top of every session. On a remote container it runs
automatically. Locally it is a no-op unless you run it yourself:

```bash
CLAUDE_CODE_REMOTE=true ./.claude/hooks/session-start.sh
```

It is idempotent and safe to re-run. If you add a Python dependency, add it to the install
list in that script **and** to `STATUS.md`, or the next session will not have it.

### When scons refuses to rebuild

After a `git restore` of the device binaries, scons thinks they are current and the link
fails with `Relocations in generic ELF (EM: 183)` or `file in wrong format`. Clear them:

```bash
./tools/clean_build_artifacts.sh --dry-run   # always look first
./tools/clean_build_artifacts.sh             # wrong-architecture artifacts only
./tools/clean_build_artifacts.sh --all       # every tracked build artifact
./tools/clean_build_artifacts.sh --sconsign  # also drop scons's own cache
```

Everything it removes is tracked, so `git restore <path>` brings it back. It is scoped to
the trees scons builds and **never touches `third_party/`** — that holds vendored *device*
libraries (`third_party/acados/larch64/`, the aarch64 h3 wheels) which are legitimately
aarch64 and are not outputs of this build. An earlier version keyed purely on "wrong
architecture" and would have deleted twelve of them; the path scope is the fix, so do not
loosen it back to a bare extension match.

`.claude/settings.json` pre-approves this script, `scons --clean`, and `rm` inside the build
trees, with `third_party/`, `.git`, `$HOME` and `sudo rm` explicitly denied.

Do not report a test as unrunnable until you have tried the recipe in `STATUS.md`.
