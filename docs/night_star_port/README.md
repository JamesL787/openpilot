Branch `night-star7` (worktree `~/nrdr/openpilot-sp7`), started 2026-10-16 from `starpilot/SecretGoodStarPilot` @ `89430a70da`.
7.0 is not released: it moves SGSP → `Dom` (dev/testing) → `StarPilot` (release). This branch gets us ready ahead of that.
`night-star7` tracks `origin/night-star7` (our fork). Never push it to the `starpilot` remote.

`night-star7` starts from **one snapshot commit** of the 7.0 tree (`e2d325132e`), not 7.0's history: that history
references ~5.3 GB of comma-master LFS models GitHub would demand in our fork's LFS store. The full-history version is
the local branch `night-star7-history`. To take a newer 7.0, apply `git diff <current base> <new SecretGoodStarPilot>` onto
`night-star7` as one "StarPilot 7.0 sync" commit and record the new base hash here.

## Conventions

- **Paths.** The tree moved under `openpilot/`; module paths did not (`openpilot.selfdrive...` is unchanged). `opendbc_repo/`,
  `panda/`, `tinygrad_repo/` stay at the root.
- **cereal.** `from cereal import X` becomes `from openpilot.cereal import X`. `car` comes from `opendbc.car.structs`.
- **LatControl.update** in 7.0 takes eight arguments (no `calibrated_pose`, `model_data`, `starpilot_toggles`). Ported
  controllers keep those three as optional keywords.
- **Tests that wait on a later slice** stay in the file and fail with an obvious import/signature error. They are not
  skipped or xfailed. Only an import that would stop the whole module from collecting moves into the test that needs it.
- **Binaries** (`*.so`, `*.a`, panda objects, params): rebuild through the Docker laptop build. Never copy a built file
  from another checkout.
- **Ledger.** Update the Status column as work lands (`todo` → `wip` → `done` / `dropped: why`). `tools/night_star_port/make_ledger.py`
  regenerates the table from git and would reset statuses, so write it to a new file and merge if it ever needs a refresh.

## Testing

`tools/night_star_port/docker_pytest.sh -q <tests>` runs pytest in the larch64 container with a venv built from 7.0's own
`uv.lock` (setup in the script header). 7.0's `tools/laptop_device_build/Dockerfile` differs from ours (capnp 1.0.1,
pinned base, ARM panda toolchain). Our `starpilot-larch64-builder` image is fine for Python tests; build 7.0's image
before any native build.

**Run the suites in two halves** (car/controls/selfdrived/modeld/locationd + cereal, then starpilot). Since SGSP
`be35d9b557` one combined process cascades into ~630 `/data/params` errno 13 failures (cereal messaging, Galaxy, FLM); it
happens identically on pristine SGSP, so it is upstream test isolation, not ours. Compare against a pristine run.

**Stopped-model guard in tests.** controlsd drops `latActive` while `modelV2` is not alive (slice 5). 7.0's own AOL already
requires `model_ready`, but engaged driving only soft-disables on `commIssue`, so the guard stays. Tests that drive
controlsd without a model (Bolt CC, Ioniq 6 AOL, LKAS-long-only, Volvo startup/lifecycle) publish a `modelV2` (or set it
alive) in their harness, marked "Night Star port".

Known environment failure, not ours: `openpilot/common/tests/test_params_fork_lock.py` (6 tests) needs 7.0's native
regression target built.

**Cover every test directory, not only the two halves.** Halves A and B left out about 25 directories (starpilot
`lateral`, `longitudinal`, `aol`, `navigation`, `controllers`, `speed_limits`, `conditional_mode`..., the GM / Hyundai /
Ford / Toyota / Tesla / Subaru / Volvo car tests, `openpilot/common`, `openpilot/system`, `tools/ci`), which hid a
controlsd regression until the 10-21 sync (a test that builds `Controls` without `__init__` lacked our `rack_map`).
Run a third half with those, on ours and on pristine, with `--import-mode=importlib` (upstream now has two test files
named `test_radar_pipeline.py`) and without `openpilot/system/{loggerd,camerad,ui,hardware}` (they abort the container:
no camera or audio devices).

**Known differences on night-star7 (Konik-only), not on night-star7-clean:** `openpilot/system/athena/tests`
(`test_athenad`, `test_registration`) and `openpilot/system/tests/test_logmessaged.py` expect the comma provider. Slice 7
makes Konik the only provider, and 7.0 keys logs, recordings and registration to the active provider; the child process
`logmessaged` cannot be patched from a test. They pass on the clean branch, whose provider is comma.

Baseline (honda car + safety tests, controls, selfdrived, car interfaces, params, state migration, starpilot honda, FLM):
**36 fail, and all 36 also fail on pristine 7.0** (the 30 below plus 6 FLM `test_operation_owner` environment failures) (27 `stock_intent` `standard_active`, `test_stock_aol`, `test_adjacent_radar_schema` schema-policy
drift, `test_leads::test_radar_fault` params path). Anything beyond those 30 is ours.
